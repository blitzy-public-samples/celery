Global Rate Limiting for Celery Workers

Enforce a task's rate across the entire worker pool — not per process.

For engineering leadership & platform owners

Section 01

The Problem

The Problem

Per-worker limiting today

  • Rate limits are enforced per worker process.
  • With N workers, a 10/s task can reach N×10/s.
  • Aggregate exceeds the intended limit by a factor of N.
Docs: a per worker instance limit — not global.
Section 02

The Solution

The Solution

One shared bucket

  • Opt-in, Redis-backed single shared token bucket coordinates all workers.
  • Aggregate throughput ≤ R for any N ≥ 1 when enabled.
  • Default-off — byte-for-byte identical behavior when disabled.

Section 03

Architecture & Integration

Architecture

End-to-end data flow

Strategy and the deferral loop stay unchanged — only the bucket object differs.

flowchart LR
  P["Producer<br/>app.send_task"] --> B["Broker queue"]
  B --> C["Worker consumer<br/>strategy.py (unchanged)"]
  C --> H{"bucket_for_task()<br/>enabled AND rate_limit?"}
  H -- No --> L["Local TokenBucket<br/>(per-worker, today)"]
  H -- Yes --> G["GlobalTokenBucket (NEW)"]
  G --> R[("Redis<br/>atomic Lua / EVALSHA")]
  R -. "Redis error" .-> F["Fail-open:<br/>warn + local bucket"]
Integration

A single integration hook

  • The only modified site is bucket_for_task() in consumer.py.
  • Enabled with a rate_limit set returns a GlobalTokenBucket; otherwise the existing bucket.
  • strategy.py and the deferral/retry loop are reused verbatim.
def bucket_for_task(self, type):
    limit = rate(getattr(type, 'rate_limit', None))
    if limit and conf.worker_enable_global_rate_limits:
        return self._global.bucket(type.name, limit)   # NEW
    return TokenBucket(limit, capacity=1) if limit else None
Atomicity

Atomic token acquisition

  • One server-side Lua script — register_script / EVALSHA.
  • Reads the Redis server clock (TIME) to avoid worker skew; capacity = 1, bounded TTL.
sequenceDiagram
  participant W as Worker (one of N)
  participant R as Redis (shared)
  W->>R: EVALSHA token script(key, fill_rate, capacity)
  R->>R: now = TIME, refill = min(cap, tokens + elapsed*rate)
  alt tokens >= 1
    R->>R: tokens -= 1, set TTL
    R-->>W: [1, 0] (allowed)
  else
    R-->>W: [0, retry_after] (deferred)
  end
Semantics

Rate units & namespacing

  • Reuses Celery's existing rate() parser — no reimplementation.
  • Buckets are namespaced per task and per rate, so budgets never collide.
10/s = 10 100/m = n ÷ 60 2/h = n ÷ 3600
celery:globalratelimit:<task>:<rate>
Safety

Fail-open by design

  • If Redis is unavailable, the limiter logs a warning and falls back to the local per-worker TokenBucket.
  • Tasks are never dropped, rejected, or dead-lettered.
  • Reuses the redis-py client from kombu[redis] — no new dependency.

Section 04

Adoption, Safety & Validation

Configuration

Two additive settings

  • worker_enable_global_rate_limits — bool, default False.
  • global_rate_limit_url — str, default None (falls back to result / broker URL).
  • Disabled means behavior is byte-for-byte identical to today.
Set via app.conf, a config module, or environment.
Validation

Observability & testing

  • Structured logging plus allow / deny / fallback counters and a fail-open warning.
  • A Grafana dashboard template ships under deliverables/.
  • Unit tests (Redis mocked) and a multi-worker integration test prove aggregate ≤ R.
